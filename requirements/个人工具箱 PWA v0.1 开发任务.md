# 我的个人工具箱 PWA v0.1 产品与开发需求

> 文档状态：v0.1 实施基线
> 目标设备：iPhone（手机优先）
> 应用名称：我的个人工具箱（Personal Toolbox）
> GitHub 仓库：`personal-toolbox`

## 1. 项目目标

“我的个人工具箱”是一个供个人长期使用的手机端 PWA。用户可以把生活、工作、学习中高频但彼此独立的小问题做成小工具，并通过统一入口快速访问。

它不是 Todo App，也不是复杂 Dashboard。v0.1 的重点是：

- 打开后能立即找到并使用工具。
- 操作步骤少，适合单手和碎片时间使用。
- 数据仅保存在本机，并可主动备份和恢复。
- 工具彼此独立，后续可以低成本增加新工具。
- 在 iPhone Safari 和“添加到主屏幕”模式下稳定运行。

## 2. v0.1 范围

### 2.1 必须实现

- 首页、收藏、设置和独立工具页。
- “最后一次”“倒计时”“灵感记录”三个工具。
- 工具注册、搜索、收藏、最近使用。
- Dexie + IndexedDB 本地持久化。
- JSON 数据导出、校验和覆盖式导入。
- 跟随系统、浅色、深色三种外观模式。
- 可安装、可离线打开的 PWA。
- GitHub Pages 自动部署。
- iPhone 安全区域和移动端键盘适配。

### 2.2 明确不做

- 登录、用户系统、后端或数据库服务器。
- 云同步、多设备同步和自动远程备份。
- AI、支付、广告和社交功能。
- 推送通知、定位、日历同步和后台定时任务。
- 多人协作和复杂权限。
- 复杂图表或 Dashboard。

除非需求文档升级版本，否则不得擅自加入以上功能。

## 3. 目标设备与兼容边界

### 3.1 主要设备

优先适配以下竖屏尺寸：

- 375 × 667
- 390 × 844
- 430 × 932

移动端内容最大宽度为 480px；桌面端仅作为居中预览和辅助使用，不单独设计复杂桌面布局。还需确保常见 iPhone 横屏下主要功能可操作。

### 3.2 iPhone PWA 限制

- iOS Safari 通常不提供网页可主动调用的通用安装弹窗。
- 设置页应根据运行环境显示“在 Safari 中打开分享菜单，再选择添加到主屏幕”的安装说明。
- 当应用已在 `standalone` 模式运行时，不再显示安装说明。
- 不承诺后台持续运行、定时唤醒或可靠推送。
- IndexedDB 可能因用户清理网站数据、卸载 PWA、系统存储压力或长期未使用而被删除，因此必须明确提示用户定期导出备份。

## 4. 技术栈与实现原则

必须使用：

- React
- Vite
- Tailwind CSS
- React Router
- Dexie
- IndexedDB
- Lucide React
- vite-plugin-pwa

实现原则：

- 使用 JavaScript 和 JSX，与 `toolRegistry.js` 及工具 `index.jsx` 命名保持一致。
- 锁定依赖版本并提交 lockfile，GitHub Actions 使用 `npm ci`。
- 不引入不必要的大型依赖；日期差等简单规则使用原生能力实现。
- 组件保持职责单一，不创建超大页面组件。
- 注释用于解释非显然的业务规则、日期边界和迁移逻辑，不要求机械地给每个函数加注释。
- 优先选择最简单、稳定、容易维护的方案。

## 5. 视觉、交互与无障碍规范

### 5.1 设计方向

关键词：简洁、现代、清晰、高可读性、工具感、少动画、少装饰。

禁止复杂 Dashboard、过度渐变、玻璃拟态、大量动画和无必要图表。视觉层级依靠字号、留白、边框和有限的强调色建立。

### 5.2 移动端规则

- 所有主要点击区域至少为 44 × 44px。
- 使用 `viewport-fit=cover`。
- 顶部和底部固定区域适配 `env(safe-area-inset-top)` 与 `env(safe-area-inset-bottom)`。
- 页面视口优先使用 `100dvh` 等动态视口单位，避免 Safari 地址栏变化造成遮挡或跳动。
- 底部导航、浮动新增按钮和表单操作区不得被 Home Indicator 或软键盘遮挡。
- 不使用仅在 hover 时才可发现的操作。
- 表单使用匹配语义的输入类型，错误信息显示在对应字段附近。
- 谨慎自动聚焦，保存后应正确收起键盘或恢复列表焦点。
- 动画仅用于必要的状态过渡，并尊重“减少动态效果”系统设置。

### 5.3 无障碍

- 图标按钮必须有可访问名称；不熟悉的图标应有提示。
- 不能仅依靠颜色表达选中、错误或危险状态。
- 文本和背景需有足够对比度。
- 页面标题层级、表单标签、焦点顺序和 VoiceOver 朗读语义应正确。
- 删除、清空和覆盖导入必须明确标识为破坏性操作。

## 6. 信息架构与导航

应用一级页面：

1. 首页
2. 收藏
3. 设置
4. 各独立工具页面

底部导航固定为：首页 / 收藏 / 设置。工具页可隐藏底部导航以减少干扰，但必须提供清晰的返回按钮。采用 `HashRouter`，路径示例：

- `/#/`
- `/#/favorites`
- `/#/settings`
- `/#/tools/last-time`
- `/#/tools/countdown`
- `/#/tools/inspiration`

使用 HashRouter 避免 GitHub Pages 刷新子页面时返回 404。

## 7. 页面需求

### 7.1 首页

顶部显示：

- 标题：我的工具箱
- 副标题：我的个人效率中心

首页按以下顺序组织：

1. 工具搜索框。
2. 最近使用，最多 4 个；无记录时不显示该分区。
3. 工具分类：生活、工作、学习。
4. 各分类下由 Tool Registry 自动生成的工具卡片。

工具卡片包含 Lucide 图标、工具名称、简短描述和收藏按钮。点击卡片进入工具；点击收藏按钮不能误触发卡片跳转。

搜索规则：

- 对名称、描述、分类和可选关键词做实时、不区分大小写的包含匹配。
- 首版验收使用“时间”“记录”“灵感”等真实可命中的词，不使用尚未注册的工具作为示例。
- 搜索结果保留分类信息。
- 无匹配时显示清晰空状态和清除搜索入口。

### 7.2 收藏页

- 标题：我的收藏。
- 根据收藏记录与 Tool Registry 生成列表，不复制工具元数据。
- 点击项目直接进入工具。
- 无收藏时显示简洁空状态，并提供返回首页的入口。
- 已禁用或移除工具不显示为可打开项目，但不得导致导入旧备份时报错。

### 7.3 设置页

外观：跟随系统、浅色、深色。用户选择需要持久化；“跟随系统”应响应系统外观变化。

数据：导出数据、导入数据、清空所有数据，以及本地数据和备份风险说明。

应用：未安装时显示适合当前浏览器的 iPhone 安装说明；已安装运行时显示“已从主屏幕运行”；不显示无法工作的伪安装按钮。

关于：我的个人工具箱，版本 0.1.0。

## 8. Tool Registry

必须创建 `src/app/toolRegistry.js`，作为工具展示元数据的单一来源。首页和收藏页不得手写工具卡片数据。

工具对象结构：

```js
{
  id,
  name,
  description,
  icon,
  category,
  path,
  enabled,
  keywords,
}
```

约束：

- `id` 全局唯一且发布后不可随意修改。
- `category` 只能是“生活”“工作”“学习”。
- `path` 与路由定义一致。
- `icon` 使用 Lucide React 图标引用。
- `keywords` 为可选字符串数组，仅用于搜索补充。
- `enabled: false` 的工具不出现在首页、搜索和收藏页。

新增工具时只应创建独立工具目录和页面、创建数据 service（如需要）、注册到 Tool Registry，并注册路由。不得修改首页或收藏页的核心生成逻辑。打开任意注册工具时，应由公共工具路由包装层统一更新最近使用记录。

## 9. 工具目录与模块边界

所有工具放在 `src/tools/` 下，例如：

```text
src/tools/last-time/
  index.jsx
  components/        # 仅在有子组件时创建
  service.js         # 有持久化数据时创建
  README.md          # 记录复杂规则时创建
```

要求：

- 工具不得直接访问其他工具的内部模块。
- 工具页面使用公共 UI 组件、主题和数据基础设施。
- 不为满足目录形式创建无内容的目录或文件。
- 跨工具能力（收藏、最近使用、备份、主题）由 app/service 层负责。

建议项目结构：

```text
src/
  app/
    router.jsx
    toolRegistry.js
  components/
    layout/
    ui/
  db/
    database.js
  pages/
    HomePage.jsx
    FavoritesPage.jsx
    SettingsPage.jsx
  services/
    backupService.js
    favoritesService.js
    settingsService.js
    toolUsageService.js
  tools/
    last-time/
    countdown/
    inspiration/
  utils/
    date.js
```

实际文件可按实现需要微调，但模块职责不得混乱。

## 10. 数据层设计

### 10.1 数据库与数据模型

使用 Dexie 管理 IndexedDB：

- 数据库名称：`PersonalToolbox`
- 初始 schema 版本：`1`
- 所有业务记录使用 `crypto.randomUUID()` 生成字符串 ID。
- 时间戳使用 ISO 8601 字符串存储。
- 业务日期使用本地自然日字符串 `YYYY-MM-DD` 存储。

至少建立以下表：

| 表名 | 主键 | 必要字段 | 建议索引 |
| --- | --- | --- | --- |
| `lastTimeRecords` | `id` | `name`, `lastDate`, `note`, `createdAt`, `updatedAt` | `name`, `lastDate`, `updatedAt` |
| `countdowns` | `id` | `name`, `targetDate`, `note`, `createdAt`, `updatedAt` | `targetDate`, `updatedAt` |
| `inspirations` | `id` | `content`, `tags`, `createdAt`, `updatedAt` | `createdAt`, `updatedAt`, `*tags` |
| `favorites` | `toolId` | `toolId`, `createdAt` | `createdAt` |
| `toolUsage` | `toolId` | `toolId`, `lastUsedAt` | `lastUsedAt` |
| `settings` | `key` | `key`, `value` | 无额外索引 |

`note` 默认为空字符串，`tags` 默认为空数组。必填文本去除首尾空白后不得为空。实现时应为字段设置合理长度上限，防止误粘贴超大内容。

### 10.2 数据访问边界

- `src/db/database.js` 只负责数据库实例、schema 和版本迁移。
- React 组件不得直接操作 Dexie 表。
- 公共 service 负责收藏、最近使用、设置、备份和跨表事务。
- 每个工具的 `service.js` 负责该工具的增删改查、排序和校验。
- 不强制使用只接受表名字符串的万能 CRUD API；类型和业务规则应保留在对应 service 中。
- 导入、清空等跨表操作必须使用 Dexie transaction，确保全部成功或全部回滚。

### 10.3 schema 升级

- 每次调整表结构必须增加 Dexie 版本号。
- 迁移必须保留可恢复的数据，不得静默丢弃用户记录。
- 迁移逻辑需用旧版数据样本验证。

## 11. 日期与时间规则

“天数”统一按用户设备当前时区的本地自然日计算，不按已经过去的 24 小时段计算。

- 今天发生的事项显示“今天”或“0 天前”。
- 昨天显示“1 天前”。
- 倒计时目标为今天时显示“就是今天”。
- 未来目标显示“还有 N 天”。
- 已过期目标显示“已过去 N 天”。
- “最后一次”的日期不得晚于今天。
- “倒计时”新增时允许选择今天或未来日期；编辑既有过期项目时允许保留过去日期。
- 日期解析不得依赖 `new Date('YYYY-MM-DD')` 的 UTC 解释，应通过统一日期工具按本地年月日处理。
- 设备跨午夜或从后台恢复后，页面应重新计算显示天数。

## 12. 工具一：最后一次

元数据：ID 为 `last-time`，名称为“最后一次”，分类为“生活”，描述为“记录生活中各种事情最后一次发生的时间”。

功能：

- 新增、编辑、删除事项。
- 一键“今天做了”，将 `lastDate` 更新为今天。
- 查看上一次日期和已经过去的自然日天数。
- 可选备注。
- 按名称实时搜索。
- 排序选项：最近发生、最久未发生、最近更新；默认“最久未发生”。

列表项显示名称和相对天数。空列表显示新增引导。右下角使用带可访问名称的新增按钮，并避开底部安全区域。

点击事项进入详情，显示名称、上一次日期、已过去天数和备注，并提供“今天做了”“编辑”“删除”。删除需要二次确认。“今天做了”后立即更新列表和详情，不新增历史记录；v0.1 仅保留最后一次日期。

## 13. 工具二：倒计时

元数据：ID 为 `countdown`，名称为“倒计时”，分类为“生活”，描述为“记录重要日期并查看距离目标还有多少天”。

功能：

- 新增、编辑、删除倒计时。
- 输入名称、目标日期和可选备注。
- 自动计算剩余或已过去的自然日天数。
- 默认按目标日期从近到远排序。
- 删除需要二次确认。

“孩子生日，还有 36 天”等示例仅用于说明，不作为预置数据写入数据库。

## 14. 工具三：灵感记录

元数据：ID 为 `inspiration`，名称为“灵感记录”，分类为“学习”，描述为“快速记录突然想到的想法”。

目标：用户进入页面后可以在约 3 秒内开始输入并保存。

功能：

- 顶部快速输入和保存。
- 编辑、删除灵感；删除需要二次确认。
- 添加零个或多个标签。
- 按内容和标签实时搜索。
- 默认按创建时间倒序排列，可切换为最近更新。

输入占位提示为“今天想到……”。标签展示示例可使用“公众号”“机器人”“控制理论”；存储时标签不包含 `#`，界面展示时统一添加。内容为空时不得保存。

## 15. 收藏与最近使用

### 15.1 收藏

- 收藏记录只保存 `toolId` 和 `createdAt`，工具名称等信息来自 Tool Registry。
- 首页工具卡片和收藏页状态保持同步。
- 重复收藏同一工具不得产生重复记录。

### 15.2 最近使用

- 每次成功进入工具首页时更新该工具的 `lastUsedAt`。
- 首页按 `lastUsedAt` 倒序显示最多 4 个。
- 同一工具只显示一次。
- 从工具内部详情页切换不新增记录，只更新时间即可。
- 收藏与最近使用是两个独立概念，不混用标题或排序。

## 16. 数据导出、导入与清空

### 16.1 导出

导出文件名：`personal-toolbox-backup.json`。

结构至少包含：

```json
{
  "version": 1,
  "appVersion": "0.1.0",
  "exportedAt": "ISO-8601 timestamp",
  "lastTimeRecords": [],
  "countdowns": [],
  "inspirations": [],
  "favorites": [],
  "toolUsage": [],
  "settings": []
}
```

- 导出前读取一致的数据快照。
- 在 iPhone 上优先调用系统分享能力；不可用时下载 JSON 文件，允许保存到“文件”App。
- 导出失败时显示明确错误，不能误报成功。

### 16.2 导入

v0.1 只支持“覆盖当前数据”，不实现合并。

流程：

1. 用户选择 JSON 文件。
2. 解析并校验文件大小、JSON 格式、备份版本、顶层结构和关键字段类型。
3. 校验失败时报告原因，不修改当前数据。
4. 校验通过后提示“是否覆盖当前数据”，并建议先导出当前数据。
5. 用户确认后，在单个事务中清空业务表并写入备份。
6. 全部成功后提示“数据恢复成功”；任一步失败则回滚并保留原数据。

可忽略未知字段，以便向前兼容；缺少关键集合、ID 冲突或关键字段类型错误时拒绝导入。未来备份版本高于当前支持版本时不得强行导入。

### 16.3 清空

- 清空所有数据包含三个工具数据、收藏、最近使用和设置。
- 必须二次确认，并明确操作无法撤销。
- 清空成功后恢复默认主题和所有空状态。
- 不删除 PWA 本身及静态缓存。

## 17. PWA 要求

使用 `vite-plugin-pwa` 提供 Web App Manifest 和 Service Worker。

Manifest 至少包含：

- `name`：Personal Toolbox / 我的个人工具箱
- `short_name`：工具箱
- `start_url`：`/personal-toolbox/`
- `scope`：`/personal-toolbox/`
- `display`：`standalone`
- 明确的 `theme_color` 和 `background_color`
- 192 × 192 PNG 图标
- 512 × 512 PNG 图标

同时提供适用于 iOS 的 `apple-touch-icon`。图标使用方形 PNG，有明确主体和合适留白，不依赖透明边缘。

离线与更新策略：

- 预缓存应用壳和构建静态资源。
- 首次成功加载后，离线重新打开应用应可使用三个本地工具。
- 不缓存无关外部资源；核心字体和图标不得依赖运行时外网。
- 新 Service Worker 可用时显示简单更新提示，由用户确认刷新，避免页面代码与数据库版本长期不一致。
- 开发环境不启用会干扰普通调试的 Service Worker 缓存。

## 18. GitHub Pages 与构建

- Vite `base` 必须配置为 `/personal-toolbox/`。
- 路由使用 HashRouter。
- 创建 `.github/workflows/deploy.yml`。
- GitHub Actions 使用官方 checkout、Node setup、Pages artifact 和 deploy actions。
- 安装使用 `npm ci`，构建使用 `npm run build`。
- workflow 使用 GitHub Pages 所需最小权限，不依赖 Cloudflare。
- 构建产物路径与 Vite `dist` 保持一致。

本地必须提供：

```bash
npm run dev
npm run build
npm run preview
```

## 19. 状态、反馈与异常处理

所有页面应覆盖：

- 首次使用空状态。
- 搜索无结果状态。
- 数据加载状态。
- 数据读写失败状态。
- 表单校验错误。
- 删除、清空和覆盖导入确认。
- 操作成功的短暂反馈，但不得用通知遮挡主要操作。

数据库初始化失败、存储空间不足或文件解析失败时，应向用户说明当前数据是否已改变。错误信息面向普通用户，不直接展示难懂的堆栈。

## 20. 隐私与安全

- 所有业务数据默认只保存在当前浏览器的 IndexedDB 中。
- 不接入分析、广告、远程日志或第三方数据服务。
- 不上传导入文件内容。
- 备份文件可能包含私人内容，导出前需用简短文字提醒妥善保管。
- 显示用户文本时依赖 React 默认转义，不使用不必要的 HTML 注入。

## 21. 详细设计开发流程

每个阶段完成后先验证并报告结果，再进入下一阶段；不要一次生成全部代码。

### Phase 1：基础工程

工作内容：创建 React + Vite 项目；安装规定依赖；配置 Tailwind CSS、基础 ESLint、Vite base、PWA manifest、图标、Service Worker 和 HashRouter；建立目录；创建 GitHub Pages workflow 骨架。

阶段验证：开发服务器可访问；`npm run build` 成功；构建产物资源路径包含 `/personal-toolbox/`；manifest 可被读取。

阶段验证：首页根据 registry 生成三个工具；底部导航和返回行为正确；直接访问所有 hash 路径无 404。

### Phase 3：IndexedDB 数据层

工作内容：创建数据库 schema v1 和数据访问 services；实现收藏、最近使用和设置持久化；建立工具 service 的统一错误处理约定；实现本地自然日工具函数。

阶段验证：刷新及关闭后重开，测试数据仍存在；重复收藏不产生重复记录；日期边界计算符合第 11 节。

### Phase 4：最后一次

工作内容：完成列表、详情、新增、编辑、删除、“今天做了”、搜索、排序和空状态。

阶段验证：完整 CRUD；未来日期被阻止；跨刷新持久化；不同排序结果正确。

### Phase 5：倒计时

工作内容：完成列表、新增、编辑、删除、日期状态和排序。

阶段验证：今天、未来、过去日期文案正确；跨午夜恢复后能重新计算。

### Phase 6：灵感记录

工作内容：完成快速录入、编辑、删除、标签、搜索和排序，处理移动键盘遮挡。

阶段验证：空内容不能保存；内容和标签均可搜索；进入页面后能快速开始记录。

### Phase 7：跨工具体验

阶段验证：工具元数据无重复硬编码；收藏即时同步；最近使用最多 4 个且顺序正确；禁用工具不出现。

### Phase 8：设置与数据管理

工作内容：完成三种主题、iOS 安装说明、导出、导入、清空和所有确认反馈。

阶段验证：导出后清空，再导入可完整恢复；非法备份不会改变原数据；主题刷新后保持。

### Phase 9：PWA 与部署

工作内容：完善图标、离线缓存、更新提示和 GitHub Actions，检查生产 base path。

阶段验证：本地 production preview 正常；离线可打开；GitHub Pages 部署后首页和所有 hash 路由正常。
